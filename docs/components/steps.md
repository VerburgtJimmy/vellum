---
title: Steps
description: Numbered procedures from headings.
---

Use steps for a procedure the reader follows in order. If the order does not matter, use
a list.

Each `##` heading inside `:::steps` starts a numbered step, and everything up to the next
`##` belongs to that step.

```md
:::steps
## Install the package
Require Vellum with Composer.

## Publish starter docs
Run `php artisan vellum:install`.
:::
```

:::steps
## Install the package
Require Vellum with Composer.

## Publish starter docs
Run `php artisan vellum:install`.
:::

## Blocks inside a step

A step can contain any Markdown, including code, callouts, tables and nested lists. The
connecting line runs the full height of each step, so a long step still reads as one
unit.

:::steps
## Require the package

```bash
composer require jimmyverburgt/vellum
```

## Publish config, stubs and assets

```bash
php artisan vellum:install
```

:::note
`vellum:install` will not overwrite files you have already edited.
:::

## Open the site

Visit `/docs`.
:::

## Rules worth knowing

Only `##` starts a step. `###` and lower headings stay ordinary headings inside the
current step, which makes them useful for dividing a long step into parts.

Content before the first `##` is rendered as it is, outside any step. A sentence of setup
can go there, although it usually reads better above the directive.

Step numbers are generated by counting the `##` headings in the block, starting at one.
Do not number the headings yourself: `## 1. Install` produces step 1 with the title
"1. Install".

Step headings appear in the table of contents like any other `h2`, which is usually
helpful for a long procedure.
